# Техническое задание: веб-приложение для прогнозирования результатов хоккейных матчей

## 1. Общая концепция

Разработай полноценное современное веб-приложение для проведения голосований среди зрителей хоккейных матчей.

Во время хоккейного матча на телевизоре или специальном экране будет отображаться QR-код. Зрители сканируют его смартфонами, переходят на сайт и прогнозируют итоговый счёт матча.

Система должна автоматически регистрировать участников, сохранять их прогнозы в базе данных, фиксировать время голосования и определять победителя после завершения матча.

**Главное правило:** если несколько участников правильно угадали итоговый счёт, побеждает тот, кто отправил правильный прогноз раньше остальных.

Приложение должно состоять из двух независимых интерфейсов:

1. Публичный сайт для зрителей.
2. Защищённая административная панель для организаторов.

## 2. Технологии

Используй следующий стек:

- Frontend: React + TypeScript.
- Стилизация: Tailwind CSS.
- Backend: Node.js + Express.
- База данных: MySQL.
- Работа с базой данных: Prisma ORM.
- Генерация QR-кодов.
- REST API для взаимодействия frontend и backend.

Архитектура должна быть понятной, расширяемой и пригодной для реального использования.

Это должно быть полноценное работающее приложение, а не просто демонстрационный интерфейс.

## 3. Публичный интерфейс зрителя

### 3.1. Переход по QR-коду

На телевизоре отображается QR-код, привязанный к конкретному матчу.

При сканировании QR-кода пользователь автоматически попадает на страницу голосования соответствующего матча.

Например:

`https://example.ru/match/15`

Пользователь не должен самостоятельно выбирать матч.

### 3.2. Автоматическая регистрация участника

При первом посещении сайта система автоматически создаёт участника в базе данных.

Каждому участнику присваивается уникальный порядковый номер:

- Участник №1
- Участник №2
- Участник №3
- Участник №11
- И так далее.

Никакой регистрации через электронную почту, телефон или пароль не требуется.

Для распознавания участника используй случайный защищённый идентификатор, сохраняемый в браузере, например через cookie.

Не используй IP-адрес или MAC-адрес как уникальный идентификатор участника. IP может совпадать у множества зрителей, а MAC-адрес недоступен обычному веб-сайту.

При повторном посещении с того же браузера пользователь должен сохранять свой номер.

Система должна предусматривать базовую защиту от повторного голосования, но учитывать, что полностью исключить повторное участие с другого устройства без дополнительной идентификации невозможно.

### 3.3. Страница голосования

Создай красивый современный интерфейс в хоккейной тематике.

На странице должны отображаться:

- Название мероприятия или турнира.
- Дата матча.
- Логотип первой команды.
- Логотип второй команды.
- Названия обеих команд.
- Заголовок «Угадай итоговый счёт матча!».
- Два поля ввода счёта.
- Кнопка «Проголосовать».
- Индивидуальный номер участника.

Пример:

**ТОРОС — ИЖСТАЛЬ**

**Как закончится сегодняшний матч?**

[Логотип Тороса]  [ 3 ] : [ 2 ]  [Логотип Ижстали]

**[Проголосовать]**

Ваш номер участника: №11

Поля должны принимать только целые неотрицательные числа. Каждое поле предназначено для счёта одной команды.

Интерфейс должен быть адаптирован в первую очередь под смартфоны.

### 3.4. Отправка прогноза

После нажатия «Проголосовать»:

1. Проверить корректность введённого счёта.
2. Сохранить прогноз в MySQL.
3. Записать точное серверное время отправки.
4. Привязать прогноз к участнику и конкретному матчу.
5. Показать сообщение об успешном голосовании.

Например:

«Ваш прогноз 3:2 принят!»

«Ваш номер участника: №11»

«Ожидайте окончания матча и объявления результатов».

Каждый участник может отправить только один прогноз на один матч.

Изменение прогноза после отправки запрещено.

Необходимо обеспечить это ограничение не только на frontend, но и на уровне backend и базы данных.

### 3.5. Состояния страницы

Предусмотри следующие состояния:

**Голосование ещё не началось**

Показывать информацию о предстоящем матче и сообщение об ожидании.

**Голосование открыто**

Показывать форму прогнозирования.

**Пользователь уже проголосовал**

Показывать его сохранённый прогноз без возможности повторного голосования.

**Голосование закрыто**

Показывать сообщение «Приём прогнозов завершён».

**Результаты опубликованы**

Показывать фактический счёт матча, команду-победителя и номер участника, выигравшего конкурс.

Обновление состояния страницы должно происходить автоматически без необходимости вручную перезагружать сайт.

## 4. Административная панель

Создай отдельную защищённую панель по адресу `/admin`.

Вход должен осуществляться по логину и паролю.

Пароли должны храниться в виде защищённых хешей.

Обычные зрители не должны иметь доступа к административным функциям и данным участников.

### 4.1. Главная страница администратора

Создай удобную панель управления со следующими показателями:

- Количество созданных матчей.
- Текущий активный матч.
- Количество участников.
- Количество отправленных прогнозов.
- Статус голосования.

Добавь список предстоящих, активных и завершённых матчей.

### 4.2. Управление командами

Администратор должен иметь возможность создавать и редактировать хоккейные команды.

Для каждой команды необходимо сохранять:

- Название.
- Логотип.
- Краткое обозначение.

Логотипы должны загружаться через административную панель.

Созданные команды сохраняются в базе данных и могут повторно использоваться для будущих матчей.

### 4.3. Создание хоккейного матча

Администратор нажимает кнопку «Создать матч».

Открывается форма:

- Домашняя команда — «Торос». Она подставляется автоматически.
- Соперник — выбор из списка команд. «Торос» в этом списке исключён.
- Дата проведения матча.
- Время начала.
- Название турнира или мероприятия.
- Необязательное описание.

После сохранения создаётся новый матч со статусом «Ожидает начала».

Система автоматически формирует уникальную ссылку голосования и QR-код.

Администратор может открыть QR-код на весь экран телевизора или скачать его в виде изображения.

### 4.4. Управление голосованием

Для каждого матча должны быть кнопки:

**«Начать голосование»**

Открывает возможность отправки прогнозов.

**«Завершить голосование»**

Немедленно прекращает приём новых прогнозов.

**«Ввести итоговый счёт»**

Позволяет указать фактический результат завершившегося матча.

**«Определить победителя»**

Запускает автоматический поиск победителя среди участников.

**«Опубликовать результаты»**

Делает результаты доступными зрителям.

Организатор должен самостоятельно управлять всеми этапами.

После закрытия голосования новые прогнозы должны отклоняться сервером независимо от состояния страницы пользователя.

## 5. Автоматическое определение победителя

После завершения хоккейного матча администратор вводит фактический счёт.

Например:

ТОРОС 3:2 ИЖСТАЛЬ

Система должна:

1. Получить все прогнозы данного матча.
2. Найти участников, указавших точно 3:2.
3. Отсортировать правильные прогнозы по времени их принятия сервером.
4. Выбрать участника, отправившего правильный прогноз раньше остальных.
5. Сохранить победителя в базе данных.

Пример:

| Участник | Прогноз | Время |
|---|---|---|
| №11 | 3:2 | 18:01:15 |
| №25 | 2:1 | 18:02:30 |
| №42 | 3:2 | 18:03:10 |
| №57 | 3:2 | 18:05:45 |

Фактический счёт: 3:2.

Победитель: **участник №11**, поскольку он первым отправил правильный прогноз.

Для разрешения ситуаций, когда несколько прогнозов имеют одинаковую временную метку, используй дополнительную сортировку по порядковому ID записи прогноза.

Если никто не угадал точный счёт, система должна показать:

«К сожалению, никто не угадал точный счёт матча».

Не назначай победителя по приблизительному результату.

После определения победителя администратор должен увидеть предварительный результат и подтвердить его публикацию.

### Важное уточнение

В хоккее необходимо учитывать овертайм и буллиты. В настройках конкурса предусмотрите явно выбранное правило: прогнозируется официальный итоговый счёт матча с учётом овертайма и серии буллитов, если они были.

Правило должно отображаться зрителям до голосования и не меняться после его открытия.

## 6. Страница результатов

После публикации итогов зрители должны видеть:

- Логотипы команд.
- Фактический счёт.
- Название победившей команды.
- Номер победителя конкурса.
- Правильный прогноз победителя.
- Время его голосования.

Например:

**МАТЧ ЗАВЕРШЁН**

ТОРОС 3:2 ИЖСТАЛЬ

**ПОБЕДИТЕЛЬ КОНКУРСА**

Участник №11

Первым угадал точный счёт 3:2!

Сделай визуально эффектный экран объявления победителя с аккуратной анимацией.

Если победителей нет, отображай соответствующее сообщение.

## 7. Экран для телевизора

Разработай отдельную страницу для вывода на большой экран.

Например:

`/display/15`

На ней должны отображаться:

- Логотипы обеих команд.
- Названия команд.
- Надпись «Угадай счёт матча!».
- Крупный QR-код.
- Инструкция «Сканируй QR-код и отправляй прогноз».
- Количество проголосовавших участников.

После завершения голосования экран должен автоматически менять состояние.

После публикации результатов — показывать фактический счёт и победителя конкурса.

Страница должна хорошо выглядеть на телевизорах с разрешением Full HD 1920×1080.

Экран телевизора не должен содержать административных кнопок.

## 8. База данных MySQL

Спроектируй полноценную реляционную базу данных.

Основные сущности:

**Teams — команды**

- ID команды.
- Название.
- Сокращённое название.
- Путь к логотипу.

**Matches — матчи**

- ID матча.
- ID первой команды.
- ID второй команды.
- Дата и время.
- Название турнира.
- Статус.
- Итоговый счёт.
- Время открытия и закрытия голосования.
- ID победителя конкурса.

**Participants — участники**

- Внутренний ID.
- Публичный порядковый номер.
- Защищённый идентификатор сессии.
- Дата создания.

**Predictions — прогнозы**

- ID прогноза.
- ID участника.
- ID матча.
- Прогноз счёта первой команды.
- Прогноз счёта второй команды.
- Точное время отправки.

**Admins — администраторы**

- ID.
- Логин.
- Хеш пароля.
- Дата создания.

Создай необходимые связи, индексы и ограничения уникальности.

Один участник может голосовать в разных матчах, но только один раз в каждом.

Все данные должны сохраняться после перезапуска сервера.

## 9. Безопасность и надёжность

Реализуй:

- Защищённую авторизацию администраторов.
- Проверку прав доступа на backend.
- Валидацию всех входящих данных.
- Защиту от SQL-инъекций.
- Ограничение частоты запросов.
- Безопасное хранение идентификаторов участников.
- Проверку статуса голосования при каждом запросе.
- Корректную обработку одновременных голосований.
- Фиксацию времени на сервере, а не на устройстве пользователя.
- Защиту от повторной отправки одного прогноза.
- Отдельные настройки подключения к базе данных через переменные окружения.

Система должна корректно работать, даже если большое количество зрителей голосуют одновременно.

## 10. Дизайн приложения

Создай профессиональный современный интерфейс, соответствующий тематике хоккея.

Основное направление:

- Тёмная цветовая палитра.
- Контрастные акцентные цвета.
- Крупные логотипы команд.
- Выразительная типографика.
- Плавные анимации.
- Аккуратные карточки и элементы управления.
- Современный спортивный стиль.

Публичный сайт должен быть максимально простым и понятным, чтобы человек любого возраста мог проголосовать за несколько секунд.

Административная панель должна быть функциональной, удобной и визуально согласованной с публичным сайтом.

Используй адаптивную вёрстку для смартфонов, планшетов и компьютеров.

## 11. Дополнительные функции

Реализуй в административной панели:

- Просмотр всех прогнозов по каждому матчу.
- Поиск участника по номеру.
- Просмотр точного времени голосования.
- Статистику количества голосов.
- Распределение прогнозируемых счетов.
- Историю завершённых матчей.
- Просмотр победителей предыдущих конкурсов.
- Экспорт результатов в CSV.

До закрытия голосования прогнозы других участников должны быть недоступны обычным зрителям.

Разработай проект последовательно:

1. Продумай архитектуру приложения.
2. Спроектируй базу данных MySQL.
3. Создай backend и API.
4. Реализуй административную панель.
5. Реализуй публичную страницу голосования.
6. Добавь генерацию QR-кодов.
7. Реализуй определение победителя.
8. Создай телевизионный экран.
9. Добавь адаптивный дизайн.
10. Протестируй основные сценарии работы.

Предусмотри обработку ошибок, загрузки, отсутствия интернет-соединения и некорректных запросов.

Добавь инструкцию по локальному запуску проекта на Windows через VS Code, установке зависимостей, настройке MySQL и последующему развёртыванию на сервере.

**Итоговая цель:** получить готовую систему, которую организаторы хоккейных матчей смогут самостоятельно использовать для создания матчей, проведения голосований, определения победителей и вывода QR-кодов и результатов на телевизор без участия разработчика.
