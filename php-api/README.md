# Развёртывание «Тороса» на PHP

Серверу нужны PHP 8.2+, расширения pdo_mysql, gd, mbstring и fileinfo, MySQL, Composer для установки QR-библиотеки и веб-сервер с HTTPS. Node.js нужен на компьютере сборки React. На хостинге приложение работает через PHP.

1. Соберите React на компьютере с Node.js 22.12+ из корня репозитория: `npm ci --ignore-scripts`, затем `npm run build`.
2. Скопируйте **содержимое** `dist/` в `php-api/public/`, сохранив `index.php` и `.htaccess`. На хостинг перенесите дерево проекта с таким же расположением файлов. Назначьте **только `php-api/public/`** корнем сайта. Если панель не позволяет менять корень, попросите поддержку направить поддомен на эту папку.
3. Настройте HTTPS и перенаправление запросов к `/api/*` и страниц React на `index.php`. Для Apache правила есть в `.htaccess` (нужны mod_rewrite и разрешение использовать файл). Для Nginx настройте `try_files $uri $uri/ /index.php?$query_string` и обработку `index.php` через PHP-FPM.
4. Из корня проекта выполните `composer install --working-dir=php-api --no-dev`. Если на хостинге нет Composer, выполните установку на компьютере с совместимым PHP и перенесите `php-api/vendor/`.
5. Создайте в корне проекта файл `.env` по примеру ниже. Параметры подключения задайте в панели хостинга или в файле вне корня сайта. Спецсимволы в пароле MySQL кодируйте для URL.

```dotenv
NODE_ENV=production
PUBLIC_BASE_URL=https://vote.example.ru
DATABASE_URL="mysql://toros:YOUR_PASSWORD@127.0.0.1:3306/toros_voting"
ADMIN_LOGIN=organizer
ADMIN_PASSWORD="YOUR_NEW_PASSWORD"
```

6. Выберите существующую базу либо создайте пустую. Перед работой с существующей базой сохраните резервную копию. Выполните `php php-api/setup.php` из корня. Скрипт создаст схему только в пустой базе, добавит таблицу ограничения запросов и недостающие команды. Существующие матчи, прогнозы и логотипы останутся в базе. Для указанного логина скрипт запишет PHP-хеш пароля и завершит его прежние сессии. Пароль должен быть от 12 до 72 байт. Старые пароли Node.js для других логинов нужно переустановить этим же скриптом по одному.
7. Откройте `/api/health` и `/admin`. Проверьте QR с телефона через мобильную сеть и проведите пробный матч. Настройте резервные копии и проверьте нагрузку перед запуском на арене.

В панели откройте матч и нажмите **Удалить матч**. После подтверждения матч, его прогнозы и результат удаляются вместе. Старый QR перестаёт открывать этот матч.

Для локальной проверки соберите React, скопируйте сборку как в шаге 2 и выполните `php -S 127.0.0.1:8000 -t php-api/public php-api/router.php`. В локальном `.env` укажите `NODE_ENV=development` и `PUBLIC_BASE_URL=http://localhost:8000`. Панель доступна на `http://localhost:8000/admin`.

Тест `node php-api/smoke.mjs` запускайте на локальном тестовом сервере с пустой отдельной базой. Он создаёт матчи, участников и прогноз, проверяет истечение дедлайна, публикует результат и удаляет созданные матчи.

## Обновление действующего сайта в ISPmanager

Выполняйте пункты по одному. Для каждого пункта ниже указан результат, который нужно увидеть перед переходом дальше.

1. В ISPmanager откройте настройки сайта `torosscore.ru` и запишите его корневую папку. В ней должен быть действующий `index.php`. Найдите его подключение к `bootstrap.php` и запишите фактическое расположение этого файла. Уточните имя действующей базы в настройках сайта или в `.env`.
2. В разделе резервных копий создайте копию файлов сайта. Проверьте наличие публичной папки, скрытых файлов, действующего `.env`, `bootstrap.php`, `.htaccess` (если используется), `vendor` и папки `images`. Если копия сайта охватывает только публичную папку, сделайте закрытую копию остальных файлов отдельно. Скачайте копии из панели.
3. В разделе «Базы данных» сделайте полный SQL-экспорт действующей базы через phpMyAdmin (структура и данные). Скачайте файл и проверьте, что он содержит таблицы `Match` и `Prediction`. Копию файлов и SQL храните вне публичной папки.
4. Дождитесь паузы между голосованиями. В phpMyAdmin выберите действующую базу и выполните во вкладке SQL `SHOW COLUMNS FROM `Match` LIKE 'votingDeadline';`. Если строка уже есть, переходите дальше. Если строк нет, выполните `ALTER TABLE `Match` ADD COLUMN `votingDeadline` DATETIME(3) NULL;` и повторите проверку. Это добавляет одно необязательное поле. Команда `setup.php` предназначена для установки и может сбросить пароль организатора.
5. Распакуйте архив обновления локально. В диспетчере файлов обновите **содержимое** публичной папки: сначала добавьте новые файлы из `public/assets/` в существующую папку `assets`. Папки `images` и `fonts`, старые файлы `assets`, `.htaccess`, `.env` и `vendor` оставьте на месте.
6. Сохраните действующие серверные настройки. В существующий `bootstrap.php` перенесите изменения из `bootstrap-deadline.patch`: функцию `votingExpired()` и изменения в `matchView()`. Если работающий файл совпадает с базовой версией, можно загрузить подготовленный `bootstrap.php` поверх него. При отличиях в настройке базы, путях или обработке эмблем сохраняйте строки сервера. Затем загрузите `public/index.php` поверх действующего входного файла, сохраняя его путь к `bootstrap.php`, и в последнюю очередь замените `public/index.html`.
7. Откройте [проверку API](https://torosscore.ru/api/health). Она должна вернуть `{"ok":true}`. Откройте [постоянный экран](https://torosscore.ru/display) и [экран матча №9](https://torosscore.ru/display/9), обновите страницу через Ctrl+F5. Убедитесь, что первый адрес остался без номера, на втором видны итоги матча №9 и на обоих экранах отображается прежняя эмблема.
8. В [панели](https://torosscore.ru/admin) проверьте существующие матчи и прогнозы. На отдельном тестовом матче проверьте сохранение, изменение и отмену дедлайна. Сканируйте QR с телефона, отправьте пробный прогноз до дедлайна и проверьте закрытие на экране после него. Для проверки запрета после дедлайна используйте второй браузер или устройство с уже открытой формой.

Для отката верните сохранённые `index.html`, `index.php` и `bootstrap.php`. Прежняя версия игнорирует добавленное поле. SQL-копию используйте только при подтверждённом повреждении базы, поскольку восстановление вернёт её к моменту экспорта.
