# Торос · Конкурс прогнозов

Зрители открывают страницу конкретного матча с QR на кубе. Организатор управляет конкурсом в отдельной панели.

| Страница | Назначение |
| --- | --- |
| `/match/1` | Мобильное голосование и результаты матча |
| `/display` | Постоянный экран арены с QR, счётчиком и итогами |
| `/display/1` | Экран, закреплённый за конкретным матчем |
| `/admin` | Команды, матчи, управление конкурсом и выгрузка прогнозов |
| `/preview` | Интерактивный дизайн-макет «Торос — Ижсталь» с примером 3:2. Запускается без базы, данные сессии не сохраняются |

## Запуск на Windows

Установите Node.js 22.12+ и MySQL 8, затем откройте папку проекта в VS Code. В MySQL создайте базу `toros_voting` с кодировкой `utf8mb4` и отдельного пользователя с правами на эту базу. Для локального запуска подойдёт и MariaDB 11.4.

В PowerShell выполните:

```powershell
Copy-Item .env.example .env
npm ci
```

В `.env` заполните `DATABASE_URL`, `ADMIN_LOGIN` и `ADMIN_PASSWORD` (12–128 символов). Спецсимволы в логине и пароле **базы данных** кодируются для URL. Не добавляйте `.env` в Git.

```powershell
npm run db:migrate
npm run db:seed
npm run api
```

Во втором терминале выполните `npm run dev` и откройте [панель организатора](http://localhost:5173/admin). Команда `db:seed` создаёт администратора и заполняет справочник из 30 команд ВХЛ сезона 2026/27. Эмблемы поставляются с приложением. Повторный запуск добавляет недостающие команды, обновляет пароль указанного администратора и завершает его текущие сессии.

Для проверки только дизайна достаточно `npm ci` и `npm run dev`. Откройте [мобильный макет](http://localhost:5173/preview).

## Проведение конкурса

1. Войдите в панель, добавьте команды и создайте матч. Время вводится по Нефтекамску (UTC+5).
2. Откройте «Экран арены» в отдельной вкладке и переведите браузер в полноэкранный режим. Для вывода изображения отдельно нажмите «Скачать QR».
3. Нажмите «Начать голосование». Сверьте QR на телефоне через ту сеть, которой будут пользоваться зрители.
4. Завершите приём прогнозов вручную или задайте «Автозакрытие голосования» по Нефтекамску (UTC+5), затем введите и сохраните официальный итоговый счёт.
5. Нажмите «Опубликовать результаты». Сервер определит победителя и сразу опубликует итоги. Телефоны и экран арены обновятся автоматически. Список прогнозов, поиск и CSV доступны в панели организатора.

Постоянный экран показывает последнее открытое голосование. Если открытых голосований нет, он показывает последний матч по времени начала, среди уже начавшихся или вышедших из ожидания. Так итоги остаются на экране при создании будущих матчей. Когда наступает время начала следующего матча или организатор открывает его голосование, экран переключается сам. Если были только будущие матчи, экран показывает ближайший.

## Развёртывание

- [Обновление действующего сайта через ISPmanager](php-api/README.md#обновление-действующего-сайта-в-ispmanager)

1. Настройте постоянную базу MySQL и резервное копирование. База не должна быть доступна из интернета напрямую.
2. Выполните `npm ci`, `npm run build`, `npm run db:migrate` и при первом запуске `npm run db:seed` с нужными переменными окружения.
3. Задайте `NODE_ENV=production` и `PUBLIC_BASE_URL` с публичным HTTPS-адресом. Он попадёт в QR-коды. Запускайте `npm start` из корня через менеджер служб с автоматическим перезапуском.
4. Направьте HTTPS-прокси на порт приложения. Если прокси находится на той же машине, задайте `HOST=127.0.0.1`. Установите `TRUST_PROXY_HOPS=1` только если входящий трафик идёт через один доверенный прокси, который сам устанавливает заголовки пересылки.
5. Проверьте `/api/health`, вход организатора и QR с отдельного телефона. Для арены проверьте нагрузку с ожидаемым числом зрителей и учтите общие IP гостевого Wi-Fi при настройке SESSION_REQUESTS_PER_MINUTE и VOTE_REQUESTS_PER_MINUTE.

В production Express обслуживает сайт и API с одного адреса. Счёт и время принятия прогноза сохраняются в базе. Ограничение MySQL запрещает две записи от одного браузера для одного матча. Победителя определяет порядок принятия точных прогнозов, при совпадении времени — ID записи.
